refactor(R4.25): carve internal/database/quiethours (repo + assertion; input stays in parent)

Move the QuietHoursRepo into its own bounded-context subpkg per ADR-011.
The QuietHoursInput type is split out into a new parent file because it
is part of the parent SettingsSerializerQuietHoursRepo interface contract
that the settings serializer still consumes — keeping it in parent breaks
the cycle that would otherwise form (parent imports subpkg for the type,
subpkg imports parent for *database.DB).

Files moved (1 src + 1 test; 6 caller files swept):
  quiet_hours_repo.go              -> quiethours/repo.go
  quiet_hours_repo_test.go         -> quiethours/repo_test.go

  quiet_hours_input.go             (NEW — extracted QuietHoursInput struct
                                    from the former quiet_hours_repo.go;
                                    must stay in parent because the
                                    SettingsSerializerQuietHoursRepo
                                    interface in settings_serializer.go
                                    references it.)

Files created in subpkg:
  quiethours/doc.go                (NEW, // Layer: adapter)
  quiethours/assertion.go          (NEW — '_ database.SettingsSerializerQuietHoursRepo
                                    = (*QuietHoursRepo)(nil)' moved out of parent
                                    settings_serializer.go L672)

Subpkg references the input type as *database.QuietHoursInput; the type
itself has no DB dep so this is a clean parent-owns-contract, subpkg-owns-
implementation split.

LESSON 35 (new): when a parent INTERFACE contract uses a struct type that
also belongs naturally to the carved subpkg, the type must STAY in parent
to avoid a cycle. Split the type into its own parent file
(<aggregate>_input.go) and have the subpkg reference database.<Type>.
This is the inverse of Lesson 34 (which moves an adapter wrapping a
concrete subpkg type INTO the subpkg).
