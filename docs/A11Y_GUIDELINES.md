# Accessibility Guidelines (a11y)

Target: **WCAG 2.1 Level AA** across all TeslaSync pages.

This document is the contract for every contributor and Copilot agent. The
companion static audit lives at [`audits/a11y-audit.md`](./audits/a11y-audit.md)
and is generated by `scripts/a11y-audit.ps1`.

---

## Required for every interactive element

1. **Accessible name** — provided via one of:
   - visible text content (`<button>Save</button>`),
   - `aria-label` (icon-only button),
   - `aria-labelledby` (controls labelled by another element).
   Never ship a button or link with neither.
2. **Visible focus ring** — keep the focus styles that ship with shared
   `<Button>`, `<Input>`, `<Toggle>` components. Never override `:focus-visible`
   to `outline: none` without an equally visible alternative.
3. **Keyboard reachability** — tab order matches visual order. Never use
   `tabIndex` values greater than `0`.
4. **Touch target ≥ 44 × 44 px** below the `md` breakpoint (WCAG 2.5.5). Use
   `h-11 w-11` or larger for icon-only controls.

## Required for every modal / popover / drawer

1. `role="dialog"` (or `role="alertdialog"` for confirmations) + `aria-modal="true"`.
2. Labelled by the visible heading via `aria-labelledby`, or `aria-label`
   when there is no heading.
3. **Focus trapped** while the dialog is open — Tab and Shift+Tab cycle
   through interactive elements inside the dialog only.
4. **Focus moved into the dialog** when it opens — first interactive element,
   or the dialog container itself (with `tabIndex={-1}`) if no interactive
   elements exist.
5. **Esc closes** the dialog.
6. **Focus restored** to the element that triggered the open when the dialog
   closes.

The shared `<Modal>` and `<Drawer>` components in `web/src/components/ui/`
already implement all six rules. Use them — do not roll your own.

## Required for every color usage

1. **Never convey state by color alone** — pair with an icon and/or text label
   (`<XCircle aria-hidden="true" /> Error: …`).
2. **Text contrast** — foreground vs background must meet 4.5 : 1 (AA). The
   audit at [`audits/contrast.md`](./audits/contrast.md) lists the project's
   approved foreground/background pairs.
3. **UI component contrast** — borders, focus rings, and icon-only controls
   vs background must meet 3 : 1.
4. **Neon accents are decoration only** — never use `text-neon-*` for body
   text. Use the toned-down `text-cyan-300` / `text-emerald-300` / etc. shades
   from `severityTokens` and `neonColorMap`. See PROHIBITED PATTERN #11 in
   `.github/copilot-instructions.md`.

## Required for motion

1. **Every framer-motion animation must consult
   `useMotionPreference()`** from `web/src/hooks/useMotionPreference.ts`.
   When `reduce === true`:
   - Pass `initial={false}` so the element renders in its `animate` state
     immediately.
   - Set `transition={{ duration: 0 }}` (or use `durationMs / 1000` from the
     hook).
   - Replace `repeat: Infinity` keyframe arrays with the steady-state value.
2. **Auto-playing motion is opt-out, not opt-in.** Heroes, ambient car
   animations, parallax, and pulse loops must collapse to static when
   reduced motion is set.
3. The global `@media (prefers-reduced-motion: reduce)` block in
   `web/src/index.css` neutralises all CSS animations and transitions as a
   safety net, but JS-driven motion (framer-motion springs, infinite loops,
   `useAnimationFrame` consumers) will not be caught by CSS — the hook is
   mandatory there.

## Required for live regions

- **Toasts** — error toasts use `role="alert"` (assertive). Success / info /
  warning toasts use `role="status"` (polite). The shared `<ToastProvider>`
  handles this — do not build ad-hoc toast UIs.
- **Status messages that are not toasts** — use `<div aria-live="polite"
  aria-atomic="true">` to announce changes to screen readers without stealing
  focus. The `<Pagination>` "showing X–Y of Z" copy is one example.
- **Async errors** that demand immediate attention — use `<AlertBanner>` from
  `@/components/feedback/AlertBanner`.

## Required for forms

1. Every `<Input>` / `<Textarea>` / `<Select>` has a visible label or an
   `aria-label`. Placeholder text is not a label.
2. Validation errors are announced — pair the field with `<ErrorText>` and
   `aria-describedby` linking the field to the error message id.
3. Required fields use `required` attribute and visual indicator (asterisk,
   "Required" suffix, …).
4. Group related fields with `<fieldset>` + `<legend>` (or
   `role="group"` + `aria-labelledby`).

## Required for data tables

- Header cells use `<th scope="col">` (or `scope="row"` for row headers).
- Sortable columns have `aria-sort="ascending|descending|none"` on the `<th>`,
  and the click target is a real `<button>` inside the cell — not click
  handlers on the `<th>` itself.
- The shared `<DataTable>` enforces both rules.

## Skip links

The application shell (`<Layout>`) provides a single "Skip to main content"
link as the first focusable element. It is `sr-only` until focused, then
visible. Pages do not need to add their own skip links.

## Tabs

Use the shared `<Tabs>` component from `@/components/ui` — it provides:
- `role="tablist"` + `role="tab"` + `aria-selected`
- Roving `tabindex` (only the active tab is in the tab order)
- Left / Right arrow keys move focus and activation between tabs
- Home / End jump to first / last enabled tab
- Disabled tabs are skipped during arrow navigation

When you render the matching content panel, give it
`role="tabpanel"` and `aria-labelledby="<tablistId>-tab-<key>"` (the id is
auto-generated; expose it via a wrapper if you need cross-component linking).

## How to verify a page

### Static

```powershell
pwsh scripts/a11y-audit.ps1
# regenerates docs/audits/a11y-audit.md with per-component counts.
```

### Browser

1. **Lighthouse** (Chrome DevTools → Lighthouse → Accessibility) — gives a
   score and lists violations against axe-core rules. Aim for ≥ 95.
2. **axe DevTools** browser extension (free) — same engine, with
   element-level highlights and remediation tips.
3. **Tab through the entire page** without a mouse:
   - First tab = "Skip to main content".
   - Every interactive element receives a visible focus ring.
   - Modals trap focus; Esc closes; focus returns to the trigger.
4. **Enable OS "Reduce motion"** (Windows Settings → Accessibility → Visual
   effects, macOS System Settings → Accessibility → Display → Reduce motion).
   Confirm hero animations, FadeIn, StaggerContainer, and Toast entrance all
   collapse to static.
5. **Screen reader smoke test** — NVDA on Windows or VoiceOver on macOS.
   Read the page top-to-bottom and confirm every widget announces its name
   and current value.

## What we explicitly do not chase

- **AAA contrast (7 : 1)** — impractical for the brand colors. AA only.
- **A separate "high contrast" theme** — Phase-40 / Prompt 10 covers light
  vs dark theme parity; OS-level high-contrast mode inherits from there.
- **Sub-2.5.5 touch targets** — we accept 44 × 44 px below `md`; smaller is
  permitted on `md+` viewports per WCAG 2.5.5 (Level AA exception for inline
  controls).

## Enforcement

These run in CI via `npm run lint` (`.github/workflows/ci.yml`) and fail the
build. Run them locally before pushing a change to any shared component:

```powershell
cd web
npm run audit:a11y-static      # runs all six in one shot
```

Individually:

```powershell
npm run audit:accessible-name  # WCAG 4.1.2 — every control is named
npm run audit:landmarks        # WCAG 1.3.1 / 2.4.6 — headings + landmarks
npm run audit:reduced-motion   # WCAG 2.2.2 — no ungoverned infinite loops
npm run audit:forced-colors    # WCAG 1.4.11 — High Contrast cascade survivability
npm run audit:sr-only          # visually-hidden discipline
npm run audit:touch-target     # WCAG 2.5.5 — 44 x 44 px
```

`audit:forced-colors` does more than grep for token text: it resolves the CSS
cascade (author rules with their specificity and source order, plus the inline
custom properties `ThemeProvider` writes onto `<html>`) and fails if the
system-colour declaration is not the one that actually wins. The same resolver
is imported by `ForcedColors.contract.test.tsx`, so the spec and the gate
cannot drift.
